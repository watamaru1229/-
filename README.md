# 第2号 (仮) - 3Dハクスラシューティングゲーム

Unityで制作した、3Dハクスラシューティングゲームです。
ゲームの「手触り（気持ちよさ）」と「プログラムの堅牢性・最適化」にこだわって制作しました。

## 開発環境
- Unity 6000.4.3f1
- 言語: C#

## 技術的な工夫とこだわり

### 1. 1万発の弾でも処理落ちしない「完全防御型・中央集権」オブジェクトプール
大量の弾やエフェクトが頻繁に生成・破棄されることによる処理落ち（GCスパイク、ネイティブ-マネージド間のUpdateオーバーヘッド）を完全に防ぐため、独自のオブジェクトプールを実装しました。

- **計算量 O(1) の動的キュー管理**: 弾データ（BulletData）ごとに専用の空きキュー（`Queue`）をDictionaryで動的に生成・管理。オブジェクトの取得・返却を常に高速処理します。
- **1万発のUpdate問題への対策（中央集権化）**: 弾オブジェクト個々の `Update` メソッドを完全に廃止。本プールクラスの単一の `Update` ループ内で、全アクティブ弾の挙動（`Tick` 処理）を一括で更新する設計にしました。これにより、Unity固有のPlayerLoop呼び出しオーバーヘッドを最小限に抑えています。
- **事前生成（Prewarm）と階層の最適化**: 起動時に指定の弾データを任意のコンテナ配下に事前生成するPrewarm機能を搭載。ゲーム中の動的生成負荷（Instantiate）を極限まで排除しています。
- **徹底した最適化と堅牢性**: Unity特有のNullチェック負荷を回避するため `ReferenceEquals` を徹底。さらに、シーン遷移時などの予期せぬオブジェクト破壊を検知して安全にスキップする生存管理フラグ（`isAlive`）と状態管理フラグによる二重返却（多重入Queueによるゾンビオブジェクト化）の防止を実装し、実務基準の堅牢性を担保しています。


### 2. 企画職の調整効率を意識した「マスターとインスタンス」の分離設計
ハクスラ要素（武器のランダムステータス生成）を実装するにあたり、設計の綺麗さとチーム開発での作業効率を意識しました。
- **工夫点**: 不変の基本情報を管理するマスターデータ（`WeaponData`：ScriptableObject）と、ゲーム実行時に動的に生成される個別の状態を保持する実体（`WeaponInstance`：通常のC#クラス）に分離しました。
- **チームへの配慮**: `WeaponInstance` を `[System.Serializable]` にすることで、プランナーやデザイナーがインスペクター上で直接パラメータの変化やランダム生成の挙動を確認・調整しやすいワークフローを実現しました。
